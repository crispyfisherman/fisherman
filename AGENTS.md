# Maintaining this skill repository

Use English for all skills, scripts, examples, and engineering reports. Treat `skills/*` as the canonical portable content. Keep frontmatter limited to name and description; host-specific controls belong in `agents/openai.yaml` or the Claude adapter generated by `scripts/install.py`. Do not hand-edit generated adapters to maintain a release.

Keep each skill independently installable, with references inside its own folder. Keep the main instruction file compact. Do not require sibling skills, providers, Cursor configuration, credentials, or a fixed model name.

Preserve the separation of intent, independent review, evidence triage, personal explanation, recurrence prevention, and system learning. A review comment is a hypothesis until supported. Never relabel an unexecuted test as a reproduction. A local-only correction must not write to the target repo, including ignored files and git metadata.

The installer must preserve unrelated skills and never overwrite conflicting paths. Generated files stay ignored. Do not add automatic PR replies, polling loops, hooks, fixes, pushing, or merging as incidental behavior. Future automation needs its own explicit scope and tests.

Run `python3 scripts/validate.py` and `python3 -m unittest discover -s tests -v` when changing instruction resources, host adapters, installation behavior, or local workspace helpers. For material behavior changes, forward-test in a fresh session with a disposable repository and the raw task; keep expected answers and diagnosis out of the reviewer packet. Record observed limitations honestly.
