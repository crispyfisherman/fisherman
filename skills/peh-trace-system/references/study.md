# Study units

Teach causal links, not a catalog of files. Use this loop:

1. **Orient:** three to seven domains/owners and the chosen user/caller behavior.
2. **Predict:** offer one optional question such as “After this request returns, which table has changed and which job has only been queued?”
3. **Trace:** explain one boundary with values, a source anchor, and its consequence.
4. **Test understanding:** invite the user to predict a changed input or failure. Wait for an answer before another deep segment.
5. **Reconcile:** identify which link is correct or missing; show the relevant code and resulting state.
6. **Connect:** link this boundary to an already-understood flow and suggest one next unit.

If the user asks for a complete report or declines interaction, deliver the full bounded flow, with optional checkpoints they can answer later. Do not force a quiz before giving useful information.

Prioritize flows with cross-domain reach or on-call value: identity/permissions, a core write, background delivery/retries, data reads/cache, and a common incident path. Choose according to the actual project rather than a fixed syllabus.

A user can ask: “Explain one unfamiliar term and walk through the expressions at that step with concrete values.” Expand that step rather than regenerate the entire system report.

Optional personal ledger: repo + revision; flow; boundaries understood; confusing terms mapped to operations; predictions and corrections; code anchors; unknown services; next unit. Store only when requested, using the user's existing Obsidian workflow if available. No automatic daily/weekly posting.
